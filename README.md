# 눈길 — 우리의 일본 스키여행

모바일을 중심으로 만든 일본 스키여행 후보 비교 페이지입니다. 6개 지역·31개 스키장 정보와 실제 지역 사진을 담았으며, GitHub Pages에서 제공하는 정적 웹사이트입니다. 배포·수정 방법은 [DEPLOY.md](DEPLOY.md)를 참고하세요.

## 열어보기

`index.html`을 Chrome, Edge, Safari 등 최신 브라우저에서 열면 됩니다. 별도 설치나 빌드가 필요하지 않습니다. HTML에 디자인·데이터·동작·지역별 실제 사진이 모두 포함되어 있고, 외부 글꼴이나 이미지 로딩이 없습니다. 사진은 Wikimedia Commons의 재사용 가능한 자료를 내장했습니다.

PC에서 모바일 화면을 보고 싶다면 압축 파일 바깥에 제공된 `mobile-preview.html`을 열거나 브라우저의 모바일 기기 미리보기를 이용하세요. `mobile-preview.html`은 같은 위치의 `japan-ski/index.html`을 표시합니다.

## 페이지에 담은 내용

- 첫 화면의 2026년 12월 달력: 내가 가능한 일정 12~31일(노란색), 추천 일정 18~31일(반투명 빨간색), 겹치는 날짜는 두 색을 함께 표시
- 원본 MD의 6개 지역, 31개 스키장, 36개 출처 링크
- 지역별 요약, 스키장별 상세 가격과 설질 특성, 항공·이동·숙박·관광 정보
- 지역·스키장 이름 검색, 관심사 필터
- 지역 최대 3곳 비교 및 이 브라우저에서의 후보 보관
- 톡방에 붙여넣을 후보 이름 복사
- 4명·스키 4일 이용료의 산정 범위와 제외 항목 안내
- 이전 시즌 참고 요금(*), 온라인·공통권·‘부터’ 조건, 핫코다 로프웨이 편도 요금 안내
- 이와테의 센다이공항과 하나마키공항 이동 기준 구분

투표와 집계는 톡방에서 진행합니다. 이 페이지의 비교함은 브라우저에 저장되는 개인 후보 목록이며, 다른 사람의 목록이나 투표 결과와 동기화되지 않습니다. 브라우저 저장이 차단된 환경에서는 현재 열린 페이지에서만 후보가 유지됩니다.

후보 복사를 브라우저가 허용하지 않으면 직접 선택해서 복사할 수 있는 문구 창을 표시합니다. 공개 배포 후에는 복사 문구에 페이지 주소도 포함합니다. 로컬 파일이나 localhost 미리보기 주소는 공유 문구에 넣지 않습니다.

## 사진 출처

메인 사진과 6개 지역 카드의 그림을 실제 지역 사진으로 교체했습니다. 메인은 니세코 사진입니다. 카드 사진의 촬영 장소, 저작자, 원본 페이지, 라이선스는 페이지 하단의 ‘사진 출처와 사용 조건’ 및 PHOTO-CREDITS.md에서 확인할 수 있습니다. 모든 사진을 HTML에 내장하여 배포할 파일은 계속 index.html 하나입니다.

## 자료의 기준

자료는 제공받은 `japan_ski.md`를 기준으로 정리했습니다. 조사일은 2026년 11월 7일, 여행 시기는 2026년 12월 말입니다. 이번 제작 과정에서는 가격·항공편을 새로 조사하지 않았습니다. 실제 예약 전에 공식 출처에서 해당 날짜와 상품 조건을 확인해야 합니다.

지역별 가격 범위는 리프트+기본 렌탈의 1인·1일 금액 × 4명 × 4일의 최저·최고 범위입니다. 숙박·항공·렌터카·의류·헬멧은 제외되고 다일권·연속 렌탈 할인도 미반영입니다. 소규모 시설과 과거 시즌 요금이 섞여 있어 지역별 같은 품질의 견적 비교는 아닙니다.

## 화면이 정해진 뒤: GitHub Pages 배포

1. 본인의 GitHub 계정으로 로그인합니다.
2. 새 저장소(프로젝트 파일 보관함)를 만듭니다. 이름 예: `japan-ski-trip`.
3. 무료 공개 저장소를 사용할 경우 공개할 수 있는 자료만 올립니다. 원본 MD는 자동으로 포함하지 않습니다.
4. 저장소의 `Add file → Upload files`로 `index.html`을 올립니다. 이 파일이 저장소의 가장 바깥에 있도록 합니다. 필요하면 이 README와 PHOTO-CREDITS.md도 함께 올릴 수 있습니다.
5. `Commit changes`를 눌러 저장합니다. commit은 이번 파일 변경 내용을 기록하는 작업입니다.
6. 저장소의 `Settings → Pages`로 이동합니다.
7. `Build and deployment → Source`에서 `Deploy from a branch`를 선택합니다.
8. 브랜치는 `main`, 폴더는 `/(root)`를 선택하고 저장합니다. 생성한 기본 브랜치 이름이 다르면 실제 브랜치를 선택합니다.
9. 배포 상태가 완료되면 Pages 화면에서 실제 주소를 확인합니다. 일반적인 프로젝트 주소 형식은 `https://계정이름.github.io/저장소이름/`입니다.
10. 휴대폰과 톡방에서 주소를 열어 보고 링크를 공유합니다.

이 과정은 GitHub 웹사이트만으로 진행할 수 있습니다. 로컬 Git 설치나 명령어 입력은 나중에 필요할 때 도입하면 됩니다. 이후에는 같은 `index.html`을 수정·업로드하고 commit하면 설정한 배포 경로로 반영됩니다.

- [배포할 브랜치와 폴더 설정](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site)

## 확인한 동작

모바일 폭과 데스크톱에서 화면을 확인하고, 검색·빈 결과·관심사 필터·최대 3곳 제한·비교 화면·후보 문구 복사·상세 화면을 반복해서 여닫는 동작을 확인했습니다. 실제 휴대폰의 카카오톡 내장 브라우저 확인은 배포 후 진행할 단계입니다.
